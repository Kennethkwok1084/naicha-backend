# API 流量评估报告

> 生成时间：2025-10-21  
> 评估范围：奶茶后端系统所有核心 API 接口

---

## 📊 执行摘要

### 单次请求流量范围
- **轻量接口**（健康检查、状态查询）：**0.2 - 0.5 KB/次**
- **中等接口**（创建订单、支付发起）：**1.5 - 2.5 KB/次**
- **重量接口**（完整菜单、数据看板）：**4 - 8 KB/次**
- **WebSocket 连接**：初始握手 ~1KB，心跳 ~0.1KB/30s

### 日流量估算（假设日均 200 单）
- **顾客端小程序**：约 **3-5 MB/天**
- **商家端管理后台**：约 **2-3 MB/天**
- **支付回调**：约 **0.3 MB/天**
- **总计**：约 **5-8 MB/天**（纯业务流量，不含图片）

### 月流量估算（30天）
- **业务数据传输**：约 **150-240 MB/月**
- **图片资源**（按 50KB/商品，20商品）：约 **1 MB**（缓存后）
- **监控指标上报**（Prometheus）：约 **10-20 MB/月**
- **总计**：约 **160-260 MB/月**

### 4. 压测场景流量预估

#### 4.1 峰值场景：午高峰（12:00-13:00）

假设高峰期订单量占日均 30%：
- 订单数：60单/小时 = 1单/分钟
- 菜单查询：峰值 QPS=5（缓存命中）
- WebSocket 推送：60次 × 0.8 KB = 48 KB

**高峰小时流量**：
- 订单创建：60 × 2 KB = 120 KB
- 支付回调：60 × 1.2 KB = 72 KB
- 菜单查询：5 req/s × 3600s × 5.5 KB × 5% miss = 50 KB（缓存命中率 95%）
- WebSocket：48 KB
- **合计**：约 **290 KB/小时**

| 接口 | 目标 QPS | 并发数 | 单次流量 | 带宽需求 |
|------|----------|--------|----------|----------|

| POST /orders | 30 | 20 | 2 KB | 60 KB/s = 0.06 MB/s |

**压测峰值带宽**：约 **0.67 MB/s（上行+下行合计）**

### 5. 网络优化建议

#### 5.1 响应压缩（Gzip/Brotli）

| 数据类型 | 原始大小 | 压缩后 | 压缩率 |
|----------|----------|--------|--------|
| JSON 菜单响应 | 5.5 KB | 1.2 KB | 78% |
| JSON 订单响应 | 0.9 KB | 0.4 KB | 56% |
| JSON 看板响应 | 2.5 KB | 0.8 KB | 68% |

**启用压缩后流量节省**：约 **60-70%**

#### 5.2 HTTP/2 多路复用

- 减少 TCP 握手开销（同域名请求复用连接）
- Header 压缩（HPACK）：请求头减少 30-50%
- **预估节省**：10-15% 总流量

#### 5.3 CDN 缓存策略

| 资源类型 | 缓存策略 | 命中率预期 | 流量节省 |
|----------|----------|------------|----------|
| 商品图片 | 7天 CDN + 浏览器 | 95% | 减少 95% 图片流量 |
| 菜单接口 | 240s 内存缓存 | 95% | 数据库查询减少 95% |
| 静态资源 | 永久缓存 + hash | 99% | 几乎无回源 |

#### 5.4 WebSocket 优化

- 心跳间隔：30s（当前）→ 60s（可选）：减少 50% 心跳流量
- 消息压缩：WebSocket permessage-deflate 扩展
- 断线重连：指数退避，避免雪崩

### 6. 带宽容量规划

#### 6.1 公网带宽需求

**日常场景**（200单/天）：
- 平均带宽：5.3 MB / 86400s ≈ **0.06 KB/s = 0.5 Kbps**
- 峰值带宽（午高峰）：290 KB / 3600s ≈ **0.08 KB/s = 0.64 Kbps**

**压测场景**（QPS=100）：
- 峰值带宽：**0.67 MB/s = 5.36 Mbps**

**建议配置**：
- **最低**：5 Mbps（满足日常 + 2倍冗余）
- **推荐**：10 Mbps（支持短期压测 + 业务增长）
- **企业**：20 Mbps（支持 3-5倍突发流量）

#### 6.2 内网带宽需求

- **应用 → 数据库**：主要是小数据包，约 **1-2 Mbps**
- **应用 → Redis**：缓存命中，约 **0.5 Mbps**
- **Celery Worker → Printer**：打印任务，约 **0.2 Mbps**

**内网建议**：**千兆网络**（1 Gbps）完全满足

#### 6.3 存储带宽需求

- **数据库写入**：200单/天 × 2 KB ≈ **400 KB/天**
- **日志写入**：约 **50 MB/天**（结构化 JSON）
- **监控指标**：约 **10 MB/天**（Prometheus）

**存储 IOPS**：<100 IOPS（PostgreSQL + SSD 足够）

## ✅ 结论与建议

### 关键发现
1. **单次 API 请求流量极小**：平均 1-5 KB，最大不超过 8 KB
2. **日流量非常低**：200单/天仅 5 MB，月流量 <200 MB
3. **带宽需求宽松**：5-10 Mbps 足够支撑日常运营
4. **优化空间**：启用 Gzip 可节省 60% 流量，CDN 可减少 95% 图片流量

### M6 部署建议
1. ✅ **公网带宽**：10 Mbps 固定（¥150-200/月）
2. ✅ **内网带宽**：千兆网络（云服务商默认配置）
3. ✅ **启用压缩**：Uvicorn/Nginx 开启 Gzip（`level=6`）
4. ✅ **CDN 加速**：商品图片走 CDN（按流量计费 ¥0.15/GB）
5. ✅ **监控指标**：Prometheus 监控带宽利用率，设置 70% 告警
