## 5. 数据库设计

### 5.1 数据库概述

#### 5.1.1 数据库选型

- **数据库类型**：关系型数据库
- **数据库产品**：PostgreSQL 14
- **字符集**：UTF-8
- **时区设置**：UTC（应用层转换为本地时区）
- **连接方式**：PgBouncer连接池代理（事务模式）

#### 5.1.2 设计原则

1. **规范化与反规范化平衡**
   - 核心表遵循第三范式（3NF）
   - 历史快照表适度冗余（订单商品名称、规格信息）
   - 避免过度JOIN，使用JSONB存储扩展属性

2. **索引策略**
   - 主键自动创建聚簇索引
   - 外键字段创建非聚簇索引
   - 高频查询条件创建复合索引
   - 状态+时间字段创建联合索引

3. **数据类型约束**
   - 金额：NUMERIC(10,2)
   - 时间：TIMESTAMPTZ（带时区）
   - 枚举：VARCHAR + CHECK约束
   - 扩展属性：JSONB

4. **审计与追溯**
   - 所有表包含created_at字段
   - 关键表包含updated_at字段（触发器自动更新）
   - 软删除策略（deleted_at，保留数据）
   - 变更记录入audit_logs表

## 6. 接口设计

### 6.1 RESTful设计规范

#### 6.1.1 URL命名规范

- **资源路径**：使用名词复数形式，如 `/orders`、`/products`
- **版本控制**：URL路径包含版本号，如 `/api/v1/orders`
- **层级关系**：不超过3层，如 `/api/v1/orders/{id}/items`
- **操作命名**：使用HTTP方法表达操作意图，避免动词出现在URL中

**示例**：
```
✓ GET    /api/v1/orders          # 获取订单列表
✓ POST   /api/v1/orders          # 创建订单
✓ GET    /api/v1/orders/{id}     # 获取订单详情
✓ PUT    /api/v1/orders/{id}     # 更新订单
✓ DELETE /api/v1/orders/{id}     # 删除订单

✗ GET    /api/v1/getOrders       # 不应在URL中使用动词
✗ POST   /api/v1/order           # 应使用复数形式
```

#### 6.1.2 HTTP方法语义

| 方法 | 语义 | 幂等性 | 安全性 | 用途 |
|------|------|--------|--------|------|
| GET | 查询资源 | 是 | 是 | 获取列表或详情 |
| POST | 创建资源 | 否 | 否 | 创建新记录 |
| PUT | 完整更新 | 是 | 否 | 替换整个资源 |
| PATCH | 部分更新 | 否 | 否 | 更新部分字段 |
| DELETE | 删除资源 | 是 | 否 | 删除记录 |

#### 6.1.3 响应状态码

| 状态码 | 含义 | 使用场景 |
|--------|------|----------|
| 200 OK | 成功 | GET/PUT/PATCH成功 |
| 201 Created | 已创建 | POST成功创建资源 |
| 204 No Content | 无内容 | DELETE成功或无返回体的操作 |
| 400 Bad Request | 请求错误 | 参数校验失败 |
| 401 Unauthorized | 未认证 | 缺少或无效的认证凭证 |
| 403 Forbidden | 无权限 | 认证通过但权限不足 |
| 404 Not Found | 资源不存在 | 请求的资源未找到 |
| 409 Conflict | 冲突 | 幂等键冲突、库存不足等 |
| 422 Unprocessable Entity | 语义错误 | 业务规则校验失败 |
| 429 Too Many Requests | 限流 | 超过访问频率限制 |
| 500 Internal Server Error | 服务器错误 | 未预期的服务端异常 |
| 503 Service Unavailable | 服务不可用 | 依赖服务故障或降级 |

#### 6.1.4 统一响应格式

**成功响应**：

#### 6.3.2 微信支付回调

**接口**：`POST /api/v1/payments/notify/wechat`

**请求头**：
```
X-Wechat-Signature: <hmac_signature>
Content-Type: application/json
```

**请求体**：
```json
{
  "event_id": "evt_20251111_001",
  "order_number": "20251111143001234-NA123456",
  "transaction_id": "wx_txn_20251111_abc123",
  "amount": "26.00",
  "currency": "CNY",
  "channel": "wechat_jsapi",
  "status": "SUCCESS",
  "paid_at": "2025-11-11T06:31:24.123Z"
}
```

**响应**（200 OK）：
```json
{
  "status": "SUCCESS"
}
```

**副作用**：
1. 写入`payment_records`表
2. 更新`orders.status`为`paid`
3. 创建`print_jobs`记录
4. 发放会员积分（按杯数累积）
5. 满10分自动发放优惠券
6. WebSocket推送新订单到商家端
7. 刷新看板缓存

**错误码**：
- `401`: 签名验证失败
- `404`: 订单不存在
- `409`: 支付金额与订单不符
